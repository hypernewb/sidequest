# Recommendation audit · 23 October 2026

The old application had real provider connections but did not use them to satisfy the intended outing. Passing contract tests demonstrated valid calls and safe filtering, not recommendation quality.

## Findings and changes

1. **Fixed candidate universe.** Every place search re-ranked the same 37 IDs. Nostalgia's highest results included Coffee Zingaro, Salon de Thé ROND and other cafés. The design/music persona overlapped heavily. The candidate restriction is removed; verified place-category tags now produce independent shopping, music, art and café pools.
2. **Wrong category eligibility.** The normalizer excluded hobby/toy/video-game stores and arcades. An activity-specific search and local primary-category checks now admit appropriate cultural retail and game venues while rejecting unrelated hotels, restaurants and incidental amenities. Live Nintendo + Comics + Games results included Akihabara Gamers, Kiddy Land, Animate Shinjuku, The Gundam Base Tokyo, Pokémon Center DX and Tamtam Hobby Shop.
3. **No task intent.** Three broad persona seeds were equally weighted, then the UI displayed popular cross-domain films, music and games. The new round asks which seed should lead, then two adaptive Qloo association questions and a Tokyo activity. Selected entity IDs, cultural tags and activity persist explicitly and reach the place request. One confirmed interest is sufficient to search.
4. **No popularity coverage objective.** The old dial primarily penalized repeated broad families. Activity searches now include a Qloo popularity <=0.8 query alongside unrestricted results. Explore/Surprise reserve lower-popularity slots when relevant candidates exist. A stronger 0.55 relative-affinity floor prevents low-score filler. Popularity is not a quality score or a guarantee of obscurity.
5. **Drops hidden and disconnected.** The only drop inventory was a separate eight-entry manually checked catalog, and persona picks did not create explicit franchise follows. Discover now previews official drops/pop-ups even before a place search and links to the full feed. Follows remain explicit; the app does not silently interpret a cultural choice as purchase intent.
6. **Fever was time-sorted, not personalized.** Six earliest matching listings were returned; no taste signal reached Fever. City searches now request pages 0 and 1 at 36 listings each, retain any successful page if the other fails, and normalize/deduplicate up to 72 eligible events before choosing six. The shortlist favors literal mentions of named interests and varies title-derived formats and venues. This is a transparent text/variety heuristic, not Qloo event affinity.
7. **Weak explanation quality.** “Qloo connects X to Y” is a statistical contribution, not an explanation of why a user would enjoy an outing. The round now records the user's own declared direction. Provider evidence stays distinct from that declared intent.

## Evidence and remaining limits

Live comparisons used public Qloo records and synthetic Nintendo/design persona signals, not a measured cohort. Removing all place-category constraints produced many hotels and restaurants, so unrestricted geographical search alone was not a fix. A loose arcade-amenity tag also flooded the top results with bars; activity candidates therefore require a suitable primary category. With the implemented categories, Nintendo's mixed query yielded 40 unique category-eligible candidates before local geographic/hour checks in the recorded run, including both higher- and lower-popularity records. Results change with provider data.

The official drop catalog remains eight manually checked entries, not comprehensive discovery or live stock. Ended windows and source checks older than 14 days disappear from discovery; there is no automatic refresh. Fever remains its own commercially available catalog, with a bounded two-page city search; independent gigs, neighborhood festivals, gallery openings and small organizer announcements can be absent. The announcement importer helps add a known official link but does not crawl the web. Broader event sourcing and a larger maintained drop inventory remain necessary for comprehensive Tokyo coverage. Strict place budgets still exclude unknown admission prices; weekly hours do not establish special-date availability.

Parent-reported live Fever MCP verification found a city count of 64 and 28 returned results on page 1 at a requested size of 36. Some provider examples were outside Tokyo; strict session, location and budget eligibility remains necessary. A larger retrieval pool does not establish broader independent-organizer coverage.

Documentation verification is source inspection of the quick-round components, question/context schemas, discover route/ranking, Fever client/normalizer, main page and drops preview. The parent separately reports live Qloo/Fever checks and browser review, including a synthetic Qloo failure followed by Skip to Tokyo activity with no stale Retry control. Those runtime observations were not independently repeated by this documentation pass. The parent reports final validation passed 62 tests, TypeScript and production build, including a pagination regression for 25 deduplicated eligible records, later-format selection, and page-one survival when page two fails. Existing `DESIGN.md` and `.impeccable/design.json` remain unchanged.

No user quality study or claim that all recommendations are now good. Further evaluation should compare persona/activity relevance, category diversity, popularity-band coverage, repeat rate, source freshness and user saves/passes against the prior system.
